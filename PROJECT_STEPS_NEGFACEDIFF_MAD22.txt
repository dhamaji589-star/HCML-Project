HCML Project Steps: Hidden Identity Recovery with NegFaceDiff / AdaptDiff
=======================================================================

Current goal
------------

We want to test whether negative identity-conditioned diffusion can recover
the hidden second identity from a face morph.

For one morph image:

  M_AB = morph containing identity A and identity B
  A    = known live/source identity
  B    = hidden identity we want to recover

The core experiment is:

  positive condition = embedding(M_AB)
  negative condition = embedding(A)
  generated output   = estimate of B

Then we evaluate whether the generated output is closer to B than to A.

What the downloaded diffusion model does
----------------------------------------

The diffusion model is a face generator.

It starts from random noise and gradually denoises it into a face image.

Because it is identity-conditioned, it receives a 512-dimensional identity
embedding/context vector. The generated face should resemble that identity.

NegFaceDiff / AdaptDiff do not train a new generator for our project.
They reuse this pretrained generator and change the sampling guidance.

The core formula in diffusion/ddpm.py is:

  eps = (1 + w) * eps_pos - w * eps_neg

Meaning:

  eps_pos = model prediction with the positive identity context
  eps_neg = model prediction with the negative identity context
  w       = negative guidance strength

For our project:

  eps_pos uses embedding(M_AB)
  eps_neg uses embedding(A)

Major adaptation we need to implement
-------------------------------------

The original repo normally samples from a context dictionary and chooses
negative contexts automatically by methods such as:

  fc   = farthest context
  cc   = closest context
  mc   = median context
  rand = random context

Our project needs explicit paired contexts:

  positive context = embedding of morph image M_AB
  negative context = embedding of known image A
  target context   = embedding of hidden image B, for evaluation only

So we will likely create a new project-specific sampling wrapper instead of
using sample.py exactly as-is.

The wrapper should still reuse:

  - checkpoint/model loading from sample.py
  - diffusion sampling functions from diffusion/ddpm.py
  - U-Net architecture from models/diffusion/unet.py
  - latent decoder if latent_diffusion is true

Step 10: Evaluate the embedding sanity check

Before running the diffusion model, check the raw morph embeddings.

Script:

  python hcml_project/scripts/evaluate_embedding_baseline.py

Input files:

  hcml_project/metadata/mad22_opencv_smoke_trials.csv
  hcml_project/metadata/mad22_opencv_smoke_embeddings.csv
  hcml_project/embeddings/mad22_opencv_smoke_embeddings.npz

Output file:

  hcml_project/metadata/mad22_opencv_smoke_baseline_eval.csv

What it computes:

  sim_morph_known  = cosine(e_M, e_A)
  sim_morph_hidden = cosine(e_M, e_B)
  margin           = sim_morph_hidden - sim_morph_known

Easy example:

  If sim_morph_known is 0.70 and sim_morph_hidden is 0.82, then:

    margin = 0.82 - 0.70 = 0.12

  A positive margin means the morph is closer to the hidden identity according
  to the face-recognition model.

Why this step matters:

  It proves that metadata, aligned images, embeddings, and cosine similarity
  evaluation are connected correctly before we spend time running diffusion.

  This is not the diffusion-model reconstruction baseline. A diffusion
  reconstruction baseline would mean reconstructing from noise and identity
  condition without the negative context.

Current smoke-test result with temporary FRmodel_FarNeg_CASIA:

  Trials evaluated:       20
  Gallery identities:     12
  Closer to hidden:       10/20
  Hidden retrieval top-1: 10/20
  Hidden retrieval top-5: 18/20
  Mean hidden rank:       2.45

Why 10/20 is understandable:

  Each morph is evaluated in two directions:

    M_AB + A -> recover B
    M_AB + B -> recover A

  If the raw morph embedding leans toward identity A, then the direction where
  A is hidden succeeds, while the opposite direction usually fails. The later
  diffusion step should use negative guidance to move away from the known
  identity and toward the hidden identity.

Image-quality diagnostic:

  python hcml_project/scripts/sample_paired_diffusion.py ^
    --max-trials 4 ^
    --setting both ^
    --ddim-steps 200 ^
    --noise-timestep 500 ^
    --output-dir hcml_project/outputs/generated_smoke_elasticface_arc_t500 ^
    --device cuda

Why this helps:

  The official project setup starts from the morph after the full forward
  diffusion process. In a 1000-step diffusion model, that means timestep 999.
  At that point, the latent is almost pure noise, so the generated image can
  become very blurry or lose visible identity details.

  The --noise-timestep option lets us test smaller values such as 500 or 250.
  This keeps more information from the morphed image before sampling. If the
  generated images become much clearer, then we know the blur is related to how
  much morph information is destroyed before reverse sampling.

Important:

  The default is still the supervisor-aligned setup, timestep 999. Smaller
  timesteps should be treated as a debugging or ablation experiment unless the
  supervisor approves using them as the main result.
